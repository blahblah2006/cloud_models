#  Everything below is a comment. Copy the commands into the Ubuntu
#  terminal of the VM named in each step.
#
#  STANDARD SETUP USED IN ALL QUESTIONS  (3 VMs)
#  ---------------------------------------------------------------
#    VM1 = LOAD BALANCER   (HAProxy)           e.g. IP 192.168.136.10
#    VM2 = WEB SERVER 1    (Apache)            e.g. IP 192.168.136.11
#    VM3 = WEB SERVER 2    (Apache)            e.g. IP 192.168.136.12
#  (Your IPs will be different. Find them with:  ip a   or   hostname -I)
#
#  VMware network setting for ALL VMs:
#    VM > Settings > Network Adapter > "NAT" (or "Bridged").
#    All VMs MUST use the SAME network type so they can see each other.
#
#  How to create a VM (do this once, then clone):
#    1. VMware > File > New Virtual Machine > choose the Ubuntu ISO.
#    2. Give it 1-2 GB RAM, 1-2 CPU, 20 GB disk, finish the install.
#    3. Right-click the finished VM > Manage > Clone > "Full clone"
#       -> make VM2 and VM3 as clones. Rename them VM1, VM2, VM3.
#    4. On every VM run:  sudo apt update
#
# =====================================================================
#  COMMON STEP A - Install the web server on VM2 and VM3
# =====================================================================
#  On VM2:
#      sudo apt install apache2 -y
#      echo "<h1>Hello from VM2 (Server 1)</h1>" | sudo tee /var/www/html/index.html
#      sudo systemctl enable --now apache2
#  On VM3:
#      sudo apt install apache2 -y
#      echo "<h1>Hello from VM3 (Server 2)</h1>" | sudo tee /var/www/html/index.html
#      sudo systemctl enable --now apache2
#  Test from VM1:   curl http://<VM2-IP>      and      curl http://<VM3-IP>
#
# =====================================================================
#  COMMON STEP B - Install and configure the load balancer on VM1
# =====================================================================
#  On VM1:
#      sudo apt install haproxy -y
#      sudo nano /etc/haproxy/haproxy.cfg
#  Go to the END of the file and add these lines (replace the IPs):
#
#      frontend web_front
#          bind *:80
#          default_backend web_servers
#
#      backend web_servers
#          balance roundrobin                  # take turns: VM2, VM3, VM2, VM3 ...
#          option httpchk GET /                # health check = fault tolerance
#          server vm2 <VM2-IP>:80 check        # 'check' = test if server is alive
#          server vm3 <VM3-IP>:80 check
#
#  Save (Ctrl+O, Enter) and exit (Ctrl+X). Then:
#      sudo haproxy -c -f /etc/haproxy/haproxy.cfg      # checks config syntax
#      sudo systemctl restart haproxy
#      sudo systemctl enable haproxy
#
#  Test the load balancing (run on VM1 or on the host browser):
#      curl http://<VM1-IP>      <- run it 4-6 times
#  Output alternates between "Hello from VM2" and "Hello from VM3".
#  That is LOAD BALANCING.
#
#  Test the fault tolerance:
#      On VM2:   sudo systemctl stop apache2     (VM2 "fails")
#      On VM1:   curl http://<VM1-IP>            <- run it many times
#  Every reply now comes from VM3 only, and the user sees NO error.
#  HAProxy detected VM2 is down (health check) and stopped sending to it.
#      On VM2:   sudo systemctl start apache2    (VM2 recovers)
#  HAProxy automatically starts using VM2 again.
#  Optional status page: add to haproxy.cfg
#      listen stats
#          bind *:8404
#          stats enable
#          stats uri /stats
#  and open  http://<VM1-IP>:8404/stats  in a browser (green = UP, red = DOWN).
#

# =====================================================================
#  Q3. SERVER CONSOLIDATION (physical -> virtual; do the LOGICAL version)
# =====================================================================
#  Meaning: Instead of running many services on many separate PHYSICAL
#  servers (each mostly idle), run them as separate VMs on ONE physical
#  machine. Result: fewer machines, less power/space/cost, higher
#  utilisation of the one machine.
#  LOGICAL consolidation (what you do in VMware):
#    Your laptop = the ONE physical server (the host).
#    1. Create 3 VMs on this one laptop, each acting as a "former server":
#         VM-A : Web server       -> sudo apt install apache2 -y
#         VM-B : Database server  -> sudo apt install mysql-server -y
#         VM-C : File server      -> sudo apt install samba -y
#       (Use small sizes: 1 CPU, 1 GB RAM each.)
#    2. Start all three VMs at the same time.
#    3. Show that they are isolated but share the same hardware:
#         On each VM run:   hostname -I        (each has its own IP)
#                           systemctl status apache2   (or mysql / smbd)
#    4. Show the resource usage on the host (Windows Task Manager >
#       Performance): CPU/RAM of ONE machine is shared by 3 servers.
#    5. Conclusion to write: "3 physical servers were consolidated onto 1
#       physical host using 3 VMs, which improves hardware utilisation
#       and reduces cost, space and power."
#  Extra (optional): VM > Snapshot > Take Snapshot to show easy backup.
#

# =====================================================================
#  Q5. CREATE MULTIPLE VMs AND MAKE THEM COMMUNICATE USING THEIR IP ADDRESSES
# =====================================================================
#  Step 1. Create VM1 and VM2 (clone) with the SAME network type (NAT or
#          Bridged) in VMware network adapter settings.
#  Step 2. Find each VM's IP:
#              VM1:   hostname -I        e.g. 192.168.136.10
#              VM2:   hostname -I        e.g. 192.168.136.11
#  Step 3. Check the connection (ping):
#              VM1:   ping -c 4 192.168.136.11
#              VM2:   ping -c 4 192.168.136.10
#          "0% packet loss" means the VMs can communicate.
#  Step 4. (Optional) Send a real message between the VMs with netcat:
#              VM2 (receiver):  nc -l 5000
#              VM1 (sender)  :  echo "Hello VM2" | nc 192.168.136.11 5000
#          "Hello VM2" appears on VM2.
#  Step 5. (Optional) Remote login with SSH:
#              VM2:  sudo apt install openssh-server -y
#              VM1:  ssh <username-of-VM2>@192.168.136.11
#  If ping fails: check both VMs use the same network type, and run
#      sudo ufw disable      (turns off the firewall for the demo).
